# 会前准备

## 先确认在准备什么

根据通知和用户目标区分：
- 听公开讲座：侧重研究问题、方法主线、必要概念与可提问点。
- 听课题组汇报：增加与上一轮进展、未决问题和已确认待办的联系。
- 用户自己汇报：侧重证据链、图表含义、方法边界、讲稿和可能被问到的问题。

优先用用户已提供的信息推断可逆的排版选择，不逐项盘问参会者、时长、地点。报告题目、会议日期或目标缺失且真正影响准备内容时，再问最关键的一项。

## 资料与准备时间

先读通知、摘要、PPT和用户指定资料，再按需要查官方项目、论文或可靠背景。参与者动态、价格、最新性能排名等变化信息需要当前核实。

只有题目时，明确只能给方向性准备，不臆测讲者的实验、结论或方法。正文访问受阻时，先说明还缺哪些内容；用户提供题目和摘要后可以继续，不重复尝试已明确被禁止的访问。

时间紧时先给一页速读版；有充分材料且用户需要，再扩展。

## 适合听报告的预习结构

1. 一句话：报告到底想解决什么具体问题。
2. 动机：目前怎么做，成本、误差或能力限制在哪里。
3. 方法流程：输入／材料 → 关键方法 → 输出 → 验证。
4. 必要概念：只选影响理解的少量词，每个词用一句通俗解释，并放回流程里。
5. 听讲重点：哪些实验能支撑主张，哪些条件可能限制结果。
6. 可提问点：围绕用户不明白的真实环节提出问题，不故意堆术语表现专业。
7. 缺口：哪些内容来自预告、哪些查过原文、哪些仍待听报告确认。

概念解释是会前背景，不是会议已发生的记录。待会议结束后，才能根据实际材料写纪要。

## 科研主线示例

以下是抽象教学例子，不代表任何讲者已经采用的方法。

机器学习势：原子结构是输入，参考计算的能量和力等是标签；模型学习近似关系，随后用于结构优化或模拟。关注数据覆盖、参考方法误差、独立测试与物理性质验证。

主动学习与微调：已有模型 → 候选结构 → 不确定性／代表性筛选 → 补标签 → 继续训练 → 验证。关注省下的是标签、训练成本还是总成本；多个模型分歧只是可靠性线索。

AI求解PDE：先区分单个问题的神经网络近似与一类问题到解场的算子映射；说明训练靠已知解还是物理残差。关注几何、材料、边界条件变化及分布外泛化。

铁电、热输运等材料报告：外场／形变／温度改变 → 原子或电子响应 → 性质变化 → 机制证据。不要因用户以前研究过某材料，就把本次报告强行套进那个材料。

## 用户自己汇报时

围绕每张关键图准备：
- 图的数据来自哪里，横纵轴、单位和误差表示什么。
- 对照组是否同条件，哪些变量被改变。
- 图支持什么结论，还有什么解释不能排除。
- 哪些结果由用户实际完成，哪些是团队、文献、AI辅助或未来计划。

可组织为“上次问题—本次完成—证据—局限—下一步—需要老师判断”。未完成的运行、未核实代码和预计效果不写成成果。

需要讲稿时提供可直接说出口的短句，保留用户真实掌握程度。若用户要求英文，优先用简单句，控制在要求时长内，不默认整篇双语。
