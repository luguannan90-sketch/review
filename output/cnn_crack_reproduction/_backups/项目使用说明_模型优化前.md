# CNN 混凝土裂缝识别项目使用说明

## 1 项目用途

本项目用于复现实验报告《基于 CNN 的混凝土表面裂缝图像识别》中的基础卷积神经网络。项目读取本地 SDNET2018 数据集，完成数据检查、模型训练、测试集评估、模型保存和单张图像预测。

当前交付形式是一个自包含的 Jupyter Notebook：

```text
output/cnn_crack_reproduction/
├─ CNN混凝土裂缝识别复现.ipynb
└─ 项目使用说明.md
```

数据集没有复制进项目，继续使用工作区中的原始数据：

```text
SDNET2018/SDNET2018/
├─ train/
│  ├─ CD/    裂缝桥面图像
│  └─ UD/    无裂缝桥面图像
└─ test/
   ├─ CP/    裂缝路面图像
   └─ UP/    无裂缝路面图像
```

## 2 运行环境

建议使用 Python 3.10 或更高版本，并安装以下依赖：

```powershell
python -m pip install torch torchvision pillow matplotlib numpy jupyter
```

如果需要使用 RTX 4060 加速训练，应根据本机显卡驱动和 CUDA 条件安装 PyTorch 官方提供的 CUDA 版本。仅检测到 NVIDIA 显卡并不代表当前 PyTorch 能调用 GPU；运行第 1、3 节代码后，应确认输出中出现：

```text
CUDA available: True
Device: cuda
```

如果显示 `False` 和 `cpu`，项目仍可运行，但完整训练耗时会明显增加。

## 4 第一次运行

Notebook 默认启用快速模式：

```python
QUICK_RUN = True
```

快速模式仅抽取少量裂缝和无裂缝图像，训练 1 个 epoch，用于检查以下流程是否正常：

- 数据集路径是否正确；
- PyTorch 和 torchvision 是否可以导入；
- 图像能否读取和预处理；
- 模型能否完成前向传播和反向传播；
- 指标、模型文件和损失曲线能否正常保存；
- 单张图像预测是否可以运行。

在 Jupyter 菜单中选择“Restart Kernel and Run All Cells”，按顺序运行全部单元。快速模式的数值不能作为正式实验结果。

## 6 Notebook 区块说明

Notebook 共 28 个单元，其中 13 个代码单元、15 个说明单元，按实验流程分为 14 节：

1. 环境导入：加载 PyTorch、torchvision、Pillow、NumPy 和 Matplotlib。
2. 实验配置：设置数据路径、输出路径、随机种子和快速或完整模式。
3. 随机种子与计算设备：固定随机性并自动选择 CPU 或 CUDA。
4. 图像预处理与标签映射：定义 Resize、ToTensor、Normalize 和类别语义。
5. 加载并检查数据集：统计训练集、测试集和各类别图像数量。
6. 构造 DataLoader：建立批量训练和测试数据加载器。
7. 定义 ConcreteCrackCNN：复现报告中的两层卷积网络。
8. 定义训练函数：封装单轮训练过程。
9. 训练模型：执行 epoch 循环并记录损失。
10. 绘制训练损失：显示并保存损失曲线。
11. 测试集评估：计算混淆矩阵及多项分类指标。
12. 保存模型与实验指标：输出模型和 JSON 结果。
13. 单张图像预测：显示测试图像及预测概率。
14. 结果解释注意事项：说明类别不平衡和跨构件测试问题。

## 8 指标解释

项目以“裂缝”为正类：

```text
uncracked = 0
cracked   = 1
```

输出指标包括：

- Accuracy：全部样本中的预测正确比例；
- Precision：预测为裂缝的样本中，实际为裂缝的比例；
- Recall：实际裂缝样本中，被模型识别出来的比例；
- Specificity：实际无裂缝样本中，被正确识别的比例；
- F1：Precision 与 Recall 的调和平均；
- Balanced Accuracy：Recall 与 Specificity 的平均值；
- TP、FP、FN、TN：混淆矩阵四项计数。

数据集中的无裂缝图像明显多于裂缝图像，因此不能只看 Accuracy。裂缝检测任务应重点关注 Recall、Precision、F1 和 Balanced Accuracy。

## 9 对原报告代码的修正

原代码分别对训练集和测试集使用 `ImageFolder`。按照文件夹字母排序，`CD/CP` 被编号为 0，`UD/UP` 被编号为 1；但原指标代码又把标签 1 当作裂缝正类，因此实际计算的是无裂缝类别的 Recall 和 F1。

本项目没有依赖目录排序，而是显式按目录首字母映射：

```python
if folder_name.startswith("C"):
    return 1  # cracked
if folder_name.startswith("U"):
    return 0  # uncracked
```

这样训练集和测试集使用一致的类别语义，所有指标均以裂缝类为正类。

## 10 模型结构

封装后的模型仍保持报告中的结构：

```text
输入 3 × 224 × 224
→ Conv2d 3→16，3×3
→ ReLU
→ MaxPool 2×2
→ Conv2d 16→32，3×3
→ ReLU
→ MaxPool 2×2
→ Flatten
→ Linear 32×56×56→128
→ ReLU
→ Linear 128→2
→ 输出 logits
```

模型最后没有添加 Softmax，因为 `CrossEntropyLoss` 直接接收 logits。只有单图预测阶段才调用 Softmax，将 logits 转换为概率。

## 11 封装方式

当前版本采用“单 Notebook 自包含封装”，具体做法如下：

- 把导入、参数、数据集、模型、训练、评估、保存和预测代码放入一个 `.ipynb` 文件；
- 用 Markdown 单元解释每个阶段，用代码单元承载可独立运行的逻辑；
- 把容易修改的参数集中到“实验配置”单元；
- 用 `QUICK_RUN` 在快速验证和完整实验之间切换；
- 数据集通过相对路径引用，不重复打包数万张原始图片；
- 训练产物统一写入 `artifacts/notebook_run/`，不覆盖原始数据；
- 模型检查点同时保存类别定义和预处理信息，减少后续预测时的配置不一致；
- 固定随机种子，提高同一环境下的可复现性。

这种封装适合课程实验、逐块讲解和参数修改。它不是独立 EXE，也不是可通过 `pip install` 安装的 Python 软件包；运行时仍需要 Python、Jupyter 和相关依赖。

## 12 常见问题

### 找不到数据集

如果出现 `找不到训练集` 或 `找不到测试集`，检查“2 实验配置”中的 `DATA_ROOT`。当前目录结构下默认路径为：

```python
DATA_ROOT = (PROJECT_ROOT / 'SDNET2018' / 'SDNET2018').resolve()
```

如果移动了 Notebook 或数据集，需要把它改为新的数据集绝对路径。

### 内存不足

降低 `BATCH_SIZE`，例如从 32 改为 16 或 8。不要修改输入尺寸，除非同时调整模型的第一个全连接层。

### 训练速度慢

先确认 `device` 是否为 `cuda`。若为 `cpu`，说明当前 PyTorch 未使用显卡。也可以先保持 `QUICK_RUN = True` 检查流程。

### 完整实验结果与报告不同

固定随机种子不能保证跨 PyTorch、CUDA、cuDNN 和硬件环境完全相同。此外，报告没有完整记录所有软件版本和训练随机状态，因此应允许一定差异。需要依据实际输出重新填写实验指标，不能直接沿用报告中的数值。

### Accuracy 很高但裂缝 Recall 很低

这是类别不平衡下的常见现象。模型可能偏向数量更多的无裂缝类别。后续可使用类别权重、加权采样、数据增强或更强的网络结构改善。
